### 0-1. 확정된 원칙

| 주제 | 결정 |
| --- | --- |
| 금융 계산 | 금액·합계·달성률·상태·점수는 **백엔드가 계산**한다. AI는 계산하지 않고 설명만 한다. |

| AI 데이터 경계 | 자체 AI 서버(Jeff·sLM)는 가맹점명까지 처리. 외부 Gemini에는 **금액·카테고리·블록 이름만** 보낸다. |

| 대상 기기 | Android 우선. iOS는 같은 코드로 후속 확장(결제 알림 감지는 Android만 가능). |

## 2. 계정 및 시작

### F-17 가입 및 로그인

| 항목 | 내용 |
| --- | --- |
| 우선순위 | P0 |
| 담당 | BE(주) · FE |
| 스프린트 | S1(API) · S2(화면) |
| 관련 기능 | F-18 |

**설명**
이메일 또는 소셜 계정(OAuth2)으로 가입·로그인하고, JWT로 세션을 유지한다. 금융기관 인증은 F-19에서 다룬다.

**사용자 흐름**

1. 시작 화면에서 가입 또는 로그인을 선택한다.
2. 인증이 끝나면 액세스·리프레시 토큰을 발급받아 secure-store에 저장한다.
3. 신규 사용자는 F-18로, 기존 사용자는 메인 화면으로 이동한다.

**예외 처리**

| 상황 | 처리 |
| --- | --- |
| 비밀번호 불일치, 소셜 인증 취소 | 사유 표시 |
| 5회 연속 실패 | 10분간 로그인 제한 |
| 액세스 토큰 만료 | 리프레시 토큰으로 자동 갱신, 실패 시 로그인 화면 |

**데이터**

- `user`: id, email, auth_provider, plan, created_at, last_login_at

**수용 기준**

- [ ]  가입·로그인·로그아웃·토큰 갱신이 동작한다.
- [ ]  다른 사용자의 리소스를 요청하면 403을 반환한다.

### F-18 동의 및 첫 사용 안내

| 항목 | 내용 |
| --- | --- |
| 우선순위 | P0 |
| 담당 | FE(주) · BE |
| 스프린트 | S2 |
| 관련 기능 | F-17, F-19, F-25 |

**설명**
필수·선택 동의를 나눠 받고, 블록 방식과 "실제 이체 없음" 원칙을 안내한 뒤 계좌 연동으로 이어진다.

**동의 항목**

| 항목 | 구분 | 거부 시 |
| --- | --- | --- |
| 서비스 이용약관 | 필수 | 가입 불가 |
| 개인정보 수집·이용 | 필수 | 가입 불가 |
| 금융 거래정보 조회 (CODEF) | 필수(연동 시) | 연동 불가, 체험 모드만 |
| AI 분석을 위한 데이터 처리 | 필수(연동 시) | 분류·제안 기능 제한 |
| 결제 알림 읽기 (Android 알림 접근) | 선택 | 실시간 반영 없음, CODEF 동기화만 |
| 푸시 알림 수신 | 선택 | 앱 내 알림함으로만 확인 |
| 금융상품 비교 정보 수신 | 선택 | F-24 미노출 |

**사용자 흐름**

1. 항목별 목적을 한 줄씩 보여 주고 동의를 받는다.
2. 첫 사용 안내 3단계를 보여 준다: ① 블록이란 ② 실제 이체는 없음 ③ AI가 질문하는 이유
3. [계좌 연동하기]와 [나중에 하기]를 같은 크기로 보여 준다.
4. 나중에 하기를 고르면 예시 데이터로 동작하는 체험 모드로 들어간다.

**예외 처리**

| 상황 | 처리 |
| --- | --- |
| 필수 동의 철회 | 영향(연동 해제, 데이터 삭제 일정) 안내 후 재확인 |
| 안내 도중 이탈 | 다음 로그인 때 다시 표시 |

**데이터**

- `consent`: user_id, item, agreed, doc_version, changed_at
- `user_setting`: onboarding_done, link_skipped

**수용 기준**

- [ ]  필수 동의 없이는 연동 화면에 들어갈 수 없다.
- [ ]  동의 이력이 문서 버전과 함께 남는다.

## 3. 거래 데이터

### F-19 계좌·카드 연동 (CODEF)

| 항목 | 내용 |
| --- | --- |
| 우선순위 | P0 |
| 담당 | BE(주) · FE |
| 스프린트 | S2 |
| 관련 기능 | F-18, F-20, F-25, F-04 |

**설명**
CODEF 계정 등록으로 connectedId를 발급받고, 이후 조회는 connectedId로만 한다. CODEF는 **확정 데이터의 기준**이며, 실시간 감지는 F-25가 맡는다. 개발 기간에는 CODEF 샌드박스와 시드 데이터를 쓴다.

**사용자 흐름**

1. 금융기관 목록에서 기관과 인증 수단을 고른다.
2. 인증정보를 CODEF 공개키로 암호화해 보내고, 발급된 connectedId만 저장한다.
3. 최근 3개월 거래와 현재 잔액을 처음 가져온다.
4. 수집이 끝나면 분류(F-20)와 초기 블록 제안(F-04)을 실행한다.

**처리 규칙**

- 정기 동기화: 하루 3회(06시·13시·20시)
- 앱 실행 시: 마지막 동기화 후 1시간이 지났으면 추가 동기화
- 마지막 거래 이후 변경분만 가져온다(증분 동기화).
- CODEF 거래가 들어오면 임시 거래와 매칭한다(F-25 대사 규칙).

**예외 처리**

| 상황 | 처리 |
| --- | --- |
| 기관 인증 실패 | 기관이 돌려준 사유 + 재시도 버튼 |
| CODEF 응답 30초 초과 | 백그라운드 재시도, "데이터를 가져오는 중" 표시 |
| 인증 만료 | 재연동 안내 |

**화면 표시**

- 연동된 기관 목록, 마지막 동기화 시각

**데이터**

- `linked_account`: id, user_id, institution, type(계좌·카드), connected_id, last_synced_at
- `transaction`: id, account_id, occurred_at, amount, direction(in·out), merchant_or_payee, balance_after, source(codef·notification·manual), status(provisional·confirmed)
- 금융기관 인증정보는 **저장하지 않는다.**

**수용 기준**

- [ ]  연동 후 3개월 거래가 앱에 보인다.
- [ ]  DB에 평문 인증정보가 없다.

### F-25 결제 알림 실시간 감지

| 항목 | 내용 |
| --- | --- |
| 우선순위 | P0 |
| 담당 | FE(주, Android 네이티브 모듈) · BE · AI |
| 스프린트 | S3~S4 |
| 관련 기능 | F-19, F-21, F-10, F-15 |

**설명**
카드사·은행·간편결제 앱의 결제 푸시 알림을 Android 알림 접근 권한(NotificationListenerService)으로 읽어, 결제 몇 초 안에 임시 거래를 만든다. Expo development build에 네이티브 모듈(config plugin)을 붙여 구현한다.

**사용자 흐름**

1. 온보딩 또는 설정에서 "결제 알림으로 바로 반영하기"를 켠다.
2. Android 설정의 알림 접근 화면으로 이동해 권한을 허용한다.
3. 결제 알림이 오면 앱이 금액·가맹점·시각·카드사를 추출해 서버로 보낸다.
4. 서버가 임시 거래를 만들고 블록 반영(F-21), 오늘 쓸 수 있는 돈(F-10), 맥락 질문(F-15)을 바로 실행한다.

**처리 규칙**

- *허용 앱 목록(화이트리스트)**에 있는 금융 앱의 알림만 처리한다. 그 밖의 알림은 읽는 즉시 버리고 저장·전송하지 않는다.
- 알림 문구 파싱은 기기 안에서 카드사별 정규식으로 한다. 실패하면 원문 일부(금액·가맹점 후보)만 서버로 보내 자체 AI 서버가 추출한다.
- 승인 취소 알림은 같은 금액·가맹점의 임시 거래를 취소 처리한다.

**대사 규칙 (임시 → 확정)**

| 조건 | 처리 |
| --- | --- |
| CODEF 거래와 금액 동일 + 시각 차 10분 이내 + 가맹점 유사도 80 이상 | 매칭, 확정 거래로 전환 |
| 금액만 다름(해외결제·부분취소 등) | CODEF 금액으로 고치고 블록 잔액 재계산 |
| 48시간 안에 매칭되는 CODEF 거래 없음 | "확인 필요" 표시, 사용자가 유지·삭제 선택 |
| CODEF에만 있는 거래(알림 누락) | 확정 거래로 바로 추가 |

**예외 처리**

| 상황 | 처리 |
| --- | --- |
| 권한 거부 | CODEF 동기화만으로 동작, 설정에서 다시 켤 수 있음 |
| 같은 결제 알림 중복 수신 | 금액·가맹점·시각(1분 이내)이 같으면 한 건으로 처리 |
| iOS | 기능 미제공, 설정 화면에서 숨김 |

**데이터**

- `transaction.source = notification`, `status = provisional`
- `notification_app_whitelist`: package_name, institution, parser_version

**수용 기준**

- [ ]  테스트 기기에서 결제 알림 수신 → 블록 반영까지 30초 이내.
- [ ]  화이트리스트 밖 앱의 알림 내용이 로그·DB 어디에도 남지 않는다.
- [ ]  시드 시나리오에서 임시 거래가 CODEF 거래와 정확히 매칭된다.

### F-26 빠른 입력

| 항목 | 내용 |
| --- | --- |
| 우선순위 | P0 |
| 담당 | AI(파서) · FE |
| 스프린트 | S2(파서) · S3(화면) |
| 관련 기능 | F-21 |

**설명**
현금 결제처럼 알림·CODEF로 잡히지 않는 지출을 한 줄 문장으로 입력한다.

**사용자 흐름**

1. 홈 화면의 + 버튼에서 "점심 8000", "어제 택시 12000"처럼 입력한다.
2. 파서가 금액·내용·날짜·카테고리를 추출해 미리보기로 보여 준다.
3. 확인하면 임시 거래로 저장한다.

**처리 규칙**

- 날짜 표현(오늘·어제·그제·요일)을 해석하고, 없으면 오늘로 둔다.
- 현금 거래는 CODEF와 매칭하지 않고 바로 확정한다. 단, 같은 금액의 ATM 출금이 있으면 이중 차감 여부를 묻는다.

**수용 기준**

- [ ]  테스트 문장 30개에서 금액·날짜 추출 정확도 95% 이상.

| 관련 기능 | F-15, F-21 |

**설명**
거래를 4단계로 분류한다. 앞 단계에서 기준을 넘으면 다음 단계로 가지 않는다. 기준값은 초기값이며 시드 정답지로 조정한다.

**분류 단계**

| 단계 | 방법 | 처리 위치 | 통과 기준 |
| --- | --- | --- | --- |
| 1 | 가맹점 사전 정확 매칭 | AI 서버 | 일치 시 확정 |
| 2 | 퍼지 매칭 (rapidfuzz) | AI 서버 | 유사도 90 이상 |
| 3 | 임베딩 유사도 | AI 서버 | 코사인 0.85 이상 |
| 4 | Jeff 판단 → 자체 sLM 분류 또는 사용자 질문 | 자체 AI 서버 | 신뢰도 0.7 미만이면 F-15 |

**카테고리 (초기 12개)**
식비 · 배달/외식 · 카페/간식 · 교통 · 주거/관리비 · 통신 · 생활/생필품 · 쇼핑/의류 · 문화/여가 · 의료/건강 · 구독료 · 기타

**이체 유형 (별도)**
더치페이 · 선물/경조사 · 빌려준 돈 · 자기 계좌 간 이동

**처리 규칙**

- 항상 묻는 거래: 간편결제·오픈마켓 결제(품목 불명), 1만 원 이상 개인 송금
- 묻지 않는 거래: 반복 송금(F-04 고정지출 탐지), 저장된 규칙에 해당하는 거래
- 사용자가 수정한 값이 자동 분류보다 우선한다. 수정한 가맹점은 그 사용자의 개인 사전에 추가되어 다음부터 1단계에서 처리된다.

**데이터**

- `transaction`: category, classify_stage, confidence, context_tag, classified_by(auto·user·rule), updated_at

**수용 기준**

- [ ]  시드 정답지 기준 카테고리 정확도 85% 이상
- [ ]  4단계(자체 AI 서버)까지 내려가는 비율 20% 이하
- [ ]  외부 LLM으로 분류 요청이 나가지 않는다.

## 4. 금융 블록

### F-21 거래의 블록 반영

| 항목 | 내용 |
| --- | --- |
| 우선순위 | P0 |
| 담당 | BE |
| 스프린트 | S2~S3 |
| 관련 기능 | F-04, F-11, F-25 |

**설명**
모든 거래는 아래 우선순위로 정확히 하나의 블록에 반영되거나 소비에서 제외된다. 임시 거래도 바로 반영하고, 확정 시 금액이 다르면 다시 계산한다.

**반영 우선순위**

1. 고정지출형 블록의 매칭 조건(가맹점·수취인 + 금액 범위)에 맞는 출금 → 해당 블록 차감, 이번 달 납부 완료 표시
2. 사용자가 지정한 카테고리 → 블록 연결(예: 여행 → 여행 블록)에 맞는 출금 → 그 블록 차감
3. 그 밖의 출금 → 기본 사용형 블록 차감
4. 더치페이 → 본인 몫만 소비, 나머지 상계 / 빌려준 돈 → '받을 돈'으로 기록, 차감 안 함
5. 자기 계좌 간 이동 → 소비에서 제외
6. 입금 → 미배분 잔액에 추가. 반복 입금(급여)이면 배분 제안 표시

**처리 규칙**

- 미배분 잔액이 0 미만이면(실제 잔액보다 블록 합이 큼) 경고를 띄우고, 어느 블록을 줄일지 사용자가 고르게 한다. 자동으로 줄이지 않는다.

**데이터**

- `transaction.block_id`, `transaction.excluded(bool)`, `receivable`(받을 돈): user_id, transaction_id, amount, settled

**수용 기준**

- [ ]  시드 1개월 거래가 모두 한 블록 또는 제외로 반영된다.
- [ ]  항상 `블록 잔액 합 + 미배분 잔액 = 실제 잔액`이 성립한다.

### F-04 블록 생성 및 규칙 설정

| 항목 | 내용 |
| --- | --- |
| 우선순위 | P0 |
| 담당 | BE(생성·탐지) · FE · AI(제안 설명) |
| 스프린트 | S2(API) · S4(AI 설명) |
| 관련 기능 | F-19, F-21, F-07 |

**블록 유형**

| 유형 | 예시 | 기본 규칙 | 생성 방식 |
| --- | --- | --- | --- |
| 사용형 | 생활비 | 월 단위 기간, 잔액 ÷ 남은 일수로 일별 가이드 | 연동 시 1개 자동 생성 |
| 목표형 | 여행, 비상금, 저축 | 목표 금액, 기한, 월 확보 금액 | 사용자 생성 |
| 고정지출형 | 월세, 통신비, 보험료 | 납부일, 납부액, 매칭 조건 | AI 제안 또는 사용자 생성 |

**사용자 흐름 (초기 제안)**

1. 연동 직후 서버가 수입(반복 입금), 고정지출, 월 평균 소비를 계산한다.
2. AI가 결과를 블록 구성안과 근거 문장으로 정리한다. 예: "지난 3개월 매월 25일 전후 김OO님께 60만 원 송금"
3. 사용자는 미리보기에서 블록을 삭제하거나 금액을 바꾼 뒤 [블록 확정]을 누른다.

**처리 규칙**

- 고정지출 탐지(서버 로직): 같은 가맹점 또는 같은 수취인에게 3회 이상 + 금액 편차 10% 이내 + 날짜 편차 3일 이내. 월세·관리비 같은 반복 송금도 여기서 잡힌다.
- 블록을 삭제하면 잔액은 미배분 잔액으로 돌아간다. 기본 블록은 삭제할 수 없다.
- 납부일이 그 달에 없으면(예: 31일) 말일로 처리한다.

**예외 처리**

| 상황 | 처리 |
| --- | --- |
| 목표 금액 0 이하 | 저장 안 함, 수정 안내 |
| 기한이 오늘 이전 | 저장 안 함, 수정 안내 |
| 납부일 1~31 범위 밖 | 저장 안 함, 수정 안내 |

**데이터**

- `block`: id, user_id, type, name, icon, balance, target_amount, start_date, due_date, rule(JSON: pay_day, pay_amount, monthly_target, match_condition), status, created_by(ai·user), version

**수용 기준**

- [ ]  시드 페르소나 3종에서 고정지출이 정답지대로 탐지된다.
- [ ]  미리보기 확인 없이 저장되는 블록이 없다.

### F-11 블록 시각화 및 상태 판정

| 항목 | 내용 |
| --- | --- |
| 우선순위 | P0(시각화·고정지출 상태) / P1(사용형·목표형 상태) |
| 담당 | FE(시각화) · BE(판정) |
| 스프린트 | S2(시각화) · S5(판정 고도화) |
| 관련 기능 | F-09, F-14 |

**설명**
블록 크기는 잔액에 비례하고, 상태는 아래 규칙으로 서버가 판정한다. AI는 상태가 바뀐 이유만 설명한다.

**상태 판정 기준**

| 유형 | 안전 | 주의 | 위험 |
| --- | --- | --- | --- |
| 사용형 | 소진율 ≤ 경과율 + 10%p | 경과율 + 10~25%p | 경과율 + 25%p 초과 또는 잔액 0 |
| 고정지출형 | 납부액 100% 확보 | 부족하지만 미배분 잔액으로 충당 가능 | 납부일 3일 전 이내 부족 + 충당 불가 |
| 목표형 | 이번 달 확보액 ≥ 월 확보 금액(예상) | 월말 예상 확보율 70~100% | 예상 확보율 70% 미만 또는 기한 내 달성 불가 예상 |
- 소진율 = 이번 기간 사용액 ÷ 기간 초 배분액
- 경과율 = 경과일 ÷ 기간 일수
- 수치는 초기값, 사용자 테스트 후 조정

**화면 표시**

- 블록 타일: 이름, 잔액, 목표 금액, 달성률, 상태 태그(색 + 텍스트)
- 홈 상단: 미배분 잔액, 오늘 쓸 수 있는 돈(F-10)

**데이터**

- `block_status_log`: block_id, from_status, to_status, reason, changed_at

**수용 기준**

- [ ]  같은 입력에는 항상 같은 상태가 나온다(단위 테스트).
- [ ]  상태 변경 이력이 남는다.

### F-02 절약 후보 확인 및 절약 제안

- 제외된 지출: '제외됨' 배지 + 사유, 사용자가 다시 포함 가능
- 카드 버튼: [목표로 설정] [관심 없음]

**수용 기준**

- [ ]  불가피 태그 거래가 후보에 나오지 않는다.

### F-03 절약 목표 설정 및 금액 계산

| 항목 | 내용 |
| --- | --- |
| 우선순위 | P0 |
| 담당 | BE(주) · FE |
| 스프린트 | S4 |
| 관련 기능 | F-02, F-05 |

**사용자 흐름**

1. 절약 제안 카드의 [목표로 설정] 또는 소비 분석의 [새 절약 목표]를 누른다.
2. 대상 카테고리, 목표 지출액, 기간(기본 1개월), 달성 시 배분할 목표형 블록(선택)을 정한다.
3. 기간 중에는 진행률을 보여 준다.
4. 기간이 끝난 다음 날 정기 동기화 후 절약액을 확정하고 알림을 보낸다.

**계산 규칙**

- 기준 지출액 = 직전 3개월 평균 (자동)
- 예상 절약액 = 기준 지출액 − 목표 지출액
- 진행률 = 현재 지출 ÷ 목표 지출액
- **확정 절약액 = 기준 지출액 − 실제 지출액** (0 미만이면 0). 목표를 넘겼어도 기준보다 적게 썼으면 그만큼 인정한다.

**예외 처리**

| 상황 | 처리 |
| --- | --- |
| 목표 지출액 ≥ 기준 지출액 | "예상 절약액 없음" 안내 |
| 종료일 < 시작일, 음수 금액 | 저장 안 함 |
| 같은 카테고리에 활성 목표 존재 | 1개만 허용 |

**데이터**

- `saving_goal`: id, user_id, category, base_amount, target_amount, actual_amount, start_date, end_date, status(active·confirmed·allocated), linked_block_id, confirmed_saving

**수용 기준**

- [ ]  기간 종료 후 확정액이 위 식대로 계산되고 F-05로 이어진다.

### F-05 절약 금액 배분

| 항목 | 내용 |
| --- | --- |
| 우선순위 | P0(직접 선택) / P1(비율 자동·AI 제안) |
| 담당 | BE · FE · AI(제안 설명) |
| 스프린트 | S4(직접) · S5(나머지) |
| 관련 기능 | F-03, F-06, F-07 |

**배분 방식**

| 방식 | 동작 | 우선순위 |
| --- | --- | --- |
| 직접 선택 | 사용자가 블록과 금액을 고른다 | P0 |
| 비율 자동 | 미리 정한 비율(예: 여행 60%, 비상금 40%)로 나눈다. 합이 100%가 아니면 저장 안 함 | P1 |

### F-24 블록 연계 금융상품 비교

| 항목 | 내용 |
| --- | --- |
| 우선순위 | P1 (정보 제공 수준) |
| 담당 | BE(주) · FE |
| 스프린트 | S5~S6 |
| 관련 기능 | F-07, F-08, F-16 |

**설명**
블록의 목적·금액·기간에 맞는 공개 상품 정보를 비교해 보여 주고, 상품을 쓰면 달라지는 금액을 절약·목표 루프에 연결한다. **가입 권유·가입 연결은 하지 않는다.**

**비교 범위**

| 블록 상황 | 보여 주는 비교 | 연결되는 값 | 시기 |
| --- | --- | --- | --- |
| 목표형, 기간 3~36개월 | 기간·월 납입액이 맞는 적금 상위 3개 (금리순) | 만기 예상 이자, 목표 달성 시점 변화 | P1 |
| 비상금 목표형 | 수시입출금·파킹형 상품 상위 3개 | 연 예상 이자 | P1 |
| 사용형 (카드 혜택) | 소비 카테고리에 맞는 카드의 월 예상 혜택 | 월 예상 절약액 | 로드맵(2년 차) |
| 고정지출형 (대출·보험) | 대환 금리 비교, 보험료 점검 | 월 상환액·보험료 감소분 | 로드맵(3년 차) |

**처리 규칙**

- 데이터 출처: 금융감독원 '금융상품 한눈에' 통합 비교공시의 예·적금 정보. 매월 1회 적재한다. 자동 수집 가능 여부와 이용 조건은 S5 전에 확인하고, 안 되면 수동 적재한 샘플 데이터로 시연한다.
- 적금 만기 이자(세전) = 월 납입액 × 개월 수 × (개월 수 + 1) ÷ 2 × 연이율 ÷ 12. 세후 금액(15.4% 원천징수)을 함께 표시한다.
- 정렬은 금리순만 제공하고 특정 금융사를 위로 올리지 않는다.
- F-18의 '금융상품 비교 정보 수신' 동의자에게만 노출한다.

**화면 표시**

- "정보 제공이며 가입 권유가 아닙니다" 문구, 금리 기준일, 출처
- 가입 버튼 없음

**데이터**

- `product`: id, type, institution, name, rate, term_months, conditions, base_date
- `product_view_event`: user_id, block_id, product_id, viewed_at

**수용 기준**

- [ ]  목표형 블록(예: 150만 원, 12개월)에서 조건에 맞는 적금 3개와 예상 이자가 나온다.
- [ ]  이자 계산이 손 계산과 같다.
